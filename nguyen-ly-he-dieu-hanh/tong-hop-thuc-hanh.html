1. Shell – Bộ Thông Dịch Lệnh

1.1 Shell là gì?

Máy tính chỉ có thể thực thi trực tiếp mã nhị phân (0 và 1). Để con người giao tiếp dễ dàng với hệ thống bằng ngôn ngữ cấp cao, hệ điều hành cung cấp một chương trình đặc biệt gọi là Shell (Bộ thông dịch lệnh).

Lưu ý: Shell không phải là một thành phần cố định trong nhân (kernel) hệ điều hành, mà là một ứng dụng giao tiếp sử dụng hệ điều hành để thực thi lệnh và thao tác tập tin.

Các loại Shell thông dụng trong Linux:

Tên Shell Tác giả / Nhà phát triển Đặc điểm & Ghi chú
BASH (Bourne-Again SHell) Brian Fox & Chet Ramey (Free Software Foundation) Là Shell mặc định và thông dụng nhất trên hầu hết các bản phân phối Linux.
CSH (C SHell) Bill Joy (University of California - BSD) Có cú pháp câu lệnh rất tương đồng với ngôn ngữ lập trình C.
KSH (Korn SHell) David Korn (AT&T Bell Labs) Tối ưu hiệu năng cho các hệ thống Unix thương mại.

Một vài câu lệnh liên quan đến Shell:

# 1. Liệt kê tất cả các loại Shell hỗ trợ trong hệ thống: $ cat /etc/shells # 2. Kiểm tra loại Shell hiện tại đang sử dụng: $ echo $SHELL /bin/bash

1.2 Khởi động Shell & Dấu nhắc (Prompt)

Trong chế độ Text/Console, Shell được mở ngay khi đăng nhập. Trong chế độ đồ họa (GUI), Shell khởi chạy khi mở ứng dụng Terminal. Dấu nhắc lệnh mặc định dành cho người dùng thường là $ (hoặc # dành cho quản trị viên root).

1.3 Shell Script là gì?

Shell Script là một file văn bản chứa tập hợp gồm nhiều câu lệnh Linux được xếp theo thứ tự. Khi thực thi file script, Shell sẽ đọc và lần lượt thi hành từng câu lệnh tự động.

2. Các Lệnh Cơ Bản & Đường Dẫn (Path) Trong Linux

2.1 Lệnh di chuyển thư mục `cd` & Lệnh `pwd`

  • pwd (Print Working Directory): Hiển thị đường dẫn tuyệt đối của thư mục làm việc hiện hành.
  • cd path: Di chuyển đến thư mục chỉ định bởi path.
  • cd (không tham số): Trở về ngay thư mục cá nhân (Home directory) của người dùng hiện tại.

2.2 Đường dẫn Tuyệt đối vs Đường dẫn Tương đối

  • Đường dẫn tuyệt đối (Absolute Path): Chỉ định đầy đủ vị trí bắt đầu từ thư mục gốc / (Ví dụ: /usr/local/bin). Luôn bắt đầu bằng /.
  • Đường dẫn tương đối (Relative Path): Tính từ vị trí hiện hành đến thư mục mục tiêu. Không bắt đầu bằng / (Ví dụ đang ở /usr gõ cd local/bin).

2.3 Ký hiệu thư mục đặc biệt:

Ký hiệu Ý nghĩa Ví dụ ứng dụng
.. Thư mục cha (Parent Directory) cd .. hoặc cd ../share
. Thư mục hiện hành (Current Directory) ./myprog (Thực thi script trong thư mục hiện tại)
~ Thư mục cá nhân (Home Directory) ./myprog ~/myfile.txt

2.4 Biến môi trường `PATH`

Biến PATH lưu trữ danh sách các đường dẫn thư mục chứa các file chương trình thực thi. Khi bạn nhập một tên lệnh, Shell sẽ tìm kiếm chương trình đó trong các thư mục định nghĩa bởi PATH.

# Xem danh sách các đường dẫn trong biến PATH: $ echo $PATH /usr/local/bin:/usr/bin:/bin:/usr/games # Thêm một đường dẫn mới vào biến PATH: $ PATH=$PATH:/root/shellscript

3. Khảo Sát Thư Mục Và File (`ls`, `less`, `file`)

3.1 Lệnh `ls` và phân tích 7 cột định dạng dài (`ls -l`)

$ ls -l -rw-r--r-- 1 root root 1205 Mar 7 10:00 install.log
Cột số Thông tin hiển thị Mô tả chi tiết
Cột (1) Quyền truy xuất & Loại file Ký tự đầu: - (file thường), d (thư mục). 9 ký tự sau phân làm 3 nhóm: Owner (3), Group (3), Other (3) với các quyền r, w, x.
Cột (2) Số lượng liên kết (Links) Số lượng nối kết cứng trỏ tới file/thư mục.
Cột (3) Chủ sở hữu (Owner) Tên tài khoản người dùng làm chủ sở hữu file.
Cột (4) Nhóm sở hữu (Group) Tên nhóm người dùng có quyền tương ứng trên file.
Cột (5) Kích thước (Size) Kích thước file tính theo đơn vị Bytes.
Cột (6) Thời gian cập nhật Ngày giờ lần cuối file được chỉnh sửa.
Cột (7) Tên File / Thư mục Tên hiển thị của đối tượng trong hệ thống.

3.2 Lệnh `less` xem văn bản theo trang

Cú pháp: $ less tên_file. Các phím điều hướng khi dùng less:

  • Page Up hoặc b: Cuộn lên 1 trang màn hình.
  • Page Down hoặc Space: Cuộn xuống 1 trang màn hình.
  • G: Nhảy trực tiếp đến dòng cuối cùng của file.
  • 1G: Nhảy về dòng đầu tiên của file.
  • /chuỗi: Tìm kiếm từ khóa chuỗi trong nội dung file.
  • n: Tìm kiếm tiếp tục kết quả trùng khớp tiếp theo.
  • q: Thoát khỏi chế độ xem file.

3.3 Lệnh `file` xác định định dạng tập tin

Cú pháp: $ file tên_file (Ví dụ: kiểm tra xem file là ASCII text, C source code, Shell script hay ELF executable binary...).

Cú pháp lệnh Chức năng & Hành vi chi tiết

4.3 Công cụ tìm kiếm file mạnh mẽ `find`

  • find /path -name "pattern": Tìm theo tên file (có phân biệt hoa/thường).
  • find /path -iname "pattern": Tìm theo tên file **không phân biệt chữ hoa/thường**.
  • find /path -type [f|d|l|b|c]: Lọc theo loại đối tượng: f (file), d (directory), l (symlink).
  • find /path -mtime -1: Tìm các file được cập nhật trong vòng 24 giờ qua.
  • find /path -size -50c: Tìm các file thường có kích thước nhỏ hơn 50 bytes (c là bytes, k là KB).

5. Quyền Truy Xuất File & Quản Lý Quyền (`chmod`, `su`, `chown`, `chgrp`)

5.1 Bảng mã Bát phân (Octal) trong lệnh `chmod`

Quyền truy cập được chia cho 3 nhóm: Owner - Group - Other. Mỗi nhóm gồm 3 bit đại diện cho r (Read=4), w (Write=2), x (Execute=1):

Giá trị Octal Ký hiệu Quyền Ý nghĩa & Trường hợp sử dụng phổ biến
777 rwx rwx rwx Mọi người đều có toàn quyền (Đọc, Ghi, Thực thi). Rất ít khi dùng vì rủi ro bảo mật.
755 rwx r-x r-x Owner có toàn quyền, Group & Other có quyền Đọc và Thực thi. Thường dùng cho chương trình/script public.
700 rwx --- --- Chỉ duy nhất Owner có toàn quyền, những người khác không có bất kỳ quyền nào. Thường dùng cho script cá nhân bảo mật.
666 rw- rw- rw- Tất cả người dùng đều có quyền Đọc và Ghi (không có quyền thực thi).
644 rw- r-- r-- Owner có quyền Đọc & Ghi, những người khác chỉ có quyền Đọc. Thường dùng cho các file dữ liệu chuẩn.
600 rw- --- --- Owner có quyền Đọc & Ghi, những người khác bị cấm hoàn toàn. Thường dùng cho file dữ liệu quan trọng.

5.2 Lệnh `su`, `chown`, `chgrp`

  • su root: Chuyển phiên làm việc sang tài khoản Superuser quản trị root. Nhập exit để thoát về user cũ.
  • chown user_moi file: Thay đổi chủ sở hữu của file/thư mục (Cần quyền root).
  • chgrp group_moi file: Thay đổi nhóm sở hữu của file/thư mục.

Khi chỉ định rõ đường dẫn tuyệt đối /usr/hello, Shell có thể truy xuất trực tiếp file ở bất kỳ vị trí nào.

Bài 6: Khảo sát quyền trên file `ls`, `sh` và thư mục `/root`

$ chmod 700 Myweb/databases $ ls -ld Myweb/databases drwx------ 2 user1 user1 4096 Mar 7 12:00 Myweb/databases

Quyền 700 (rwx------) đảm bảo chỉ người làm chủ (hoặc root) mới có quyền truy cập, mọi người dùng khác bị chặn hoàn toàn.

Bài 13: Thiết lập quyền cho `Myweb/java` (Owner toàn quyền, người khác chỉ thực thi)
$ chmod 711 Myweb/java $ ls -ld Myweb/java drwx--x--x 2 user1 user1 4096 Mar 7 12:00 Myweb/java

Quyền 711 (rwx--x--x) cho phép Owner có quyền rwx (7), còn Group và Others chỉ có quyền thực thi x (1) để truy nhập qua thư mục nhưng không đọc được danh sách file bên trong.

Bài 14: Ý nghĩa của lệnh `chmod 755 hello` trong Bài 3

Lệnh chmod 755 hello có ý nghĩa phân quyền bát phân cho file hello như sau:

  • Chủ sở hữu (Owner = 7 = `rwx`): Có đầy đủ quyền Đọc, Ghi và Thực thi file.
  • Nhóm sở hữu (Group = 5 = `r-x`): Có quyền Đọc và Thực thi file, không có quyền chỉnh sửa.
  • Người dùng khác (Other = 5 = `r-x`): Có quyền Đọc và Thực thi file, không có quyền chỉnh sửa.

1. Viết Và Thực Thi Một Shell Script Như Thế Nào?

Quy trình chuẩn gồm 3 bước để tạo và chạy một Shell script trong Linux:

  1. Bước 1: Soạn thảo script: Sử dụng bất kỳ trình soạn thảo văn bản nào (như gedit, nano, vi...) để nhập các câu lệnh.
  2. Bước 2: Cấp quyền thực thi: Sử dụng lệnh chmod 755 tên_script để phân quyền cho phép chạy. nếu thiếu bước này, khi chạy trực tiếp sẽ bị báo lỗi Permission denied.
  3. Bước 3: Thực thi script: Thực hiện theo 1 trong các cú pháp:
    $ bash tên_script
    $ sh tên_script
    $ ./tên_script

Ví dụ script đầu tiên `firstscript`:

#!/bin/bash clear echo "This is my first script!!!"
$ chmod 755 firstscript $ ./firstscript [Màn hình được xóa sạch và hiển thị dòng chữ:] This is my first script!!!

Làm thế nào để Shell định vị được Script cần thực thi?

  • Cách 1: Sử dụng đường dẫn tuyệt đối: Chỉ định chính xác vị trí thư mục của file script (ví dụ: $ sh /root/shellscript/hello).
  • Cách 2: Sử dụng biến môi trường `PATH`: Thêm đường dẫn chứa script vào biến PATH (ví dụ: PATH=$PATH:/root/shellscript), giúp bạn có thể gọi tên script ở bất kỳ thư mục nào.

Bài tập mẫu đầu tiên:

#!/bin/bash clear echo "Hello $USER" echo -e "Today is \c"; date echo -e "Number of user login : \c"; who | wc -l echo "Calendar" cal exit 0

2. Thao Tác Biến Trong Shell

Biến được dùng để lưu trữ và quản lý dữ liệu trong bộ nhớ RAM. Biến trong Linux Shell được chia thành 2 loại:

2.1 Biến Hệ Thống (System Variables)

Được tạo ra và quản lý bởi Linux, tên biến thường được quy ước viết bằng chữ IN HOA:

Tên biến môi trường Ý nghĩa & Giá trị lưu trữ
$BASH Tên đường dẫn đến bộ thông dịch Shell đang dùng (ví dụ: /bin/bash)
$BASH_VERSION Phiên bản hiện tại của BASH Shell
$HOME Đường dẫn đến thư mục cá nhân (Home directory) của người dùng
$LOGNAME / $USER Tên tài khoản người dùng đang đăng nhập
$OSTYPE Loại hệ điều hành (ví dụ: linux-gnu)
$PATH Danh sách các đường dẫn thư mục tìm kiếm chương trình thực thi
$PWD Đường dẫn thư mục làm việc hiện hành (Print Working Directory)

Tổng Quan Về Kiểu Boolean Trong Shell

Trong Shell của Linux, giá trị True (Đúng) và False (Sai) được thể hiện tương ứng bằng 2 giá trị:

  • 0 (Zero - Exit status bằng 0): Tương ứng với True (Thành công).
  • Khác 0 (Non-zero - Exit status khác 0): Tương ứng với False (Thất bại/Lỗi).
Ví dụ: 5 > 2 => 0 (True / Thành công) 5 < 2 => 1 (False / Thất bại)

1. Câu Lệnh if

Câu lệnh if được dùng để thiết lập quyết định (lệnh rẽ nhánh) trong shell script.

Cú pháp cơ bản:

if condition then command1 command2 ... fi

Lệnh command1 được thực thi khi điều kiện condition là True (trả về 0). Ngược lại, lệnh tiếp theo sau từ khóa fi sẽ được thực hiện.

Ví dụ script rmif (Xóa file nhận từ tham số):

#!/bin/bash if rm $1 then echo "$1 is deleted successfully" fi
$ chmod +x rmif $ ./rmif aaaa rm: cannot remove 'aaaa': No such file or directory $ ./rmif a a is deleted successfully

Giải thích: Lần 1 thực thi với aaaa không tồn tại nên lệnh rm trả về exit status khác 0 (False), lệnh echo không được thực hiện. Lần 2 thực thi với file a có tồn tại nên rm thành công (exit status = 0 / True), lệnh echo được in ra màn hình.

2. Lệnh test Hoặc [ expr ]

Lệnh test hoặc [ expr ] dùng để kiểm tra một biểu thức logic là True hay False. Nếu biểu thức đúng sẽ trả về giá trị 0, ngược lại trả về giá trị khác không.

Ví dụ script ispositive:

#!/bin/bash if test $1 -gt 0 then echo "$1 is positive number" fi
$ chmod +x ispositive $ ./ispositive 5 5 is positive number $ ./ispositive -3 $

Phép toán Ý nghĩa Dùng với test Dùng với [ expr ]
-eq So sánh bằng (==) if test 5 -eq 6 if [ 5 -eq 6 ]
-ne Không bằng (!=) if test 5 -ne 6 if [ 5 -ne 6 ]
-lt Nhỏ hơn (<) if test 5 -lt 6 if [ 5 -lt 6 ]

-gt Lớn hơn (>) if test 5 -gt 6 if [ 5 -gt 6 ]
-ge Lớn hơn hoặc bằng (>=) if test 5 -ge 6 if [ 5 -ge 6 ]

b) So sánh Chuỗi ký tự (String Comparison):

Phép toán Ý nghĩa Dùng với test Dùng với [ expr ]

!= So sánh chuỗi không bằng nhau if test "aa" != "bb" if [ "aa" != "bb" ]

1. Tiến Trình Và Cách Thức Thực Hiện Tiến Trình

1.1 Mục đích của Shell đối với Tiến trình

Shell là một chương trình thông dịch lệnh hoạt động theo chu trình vòng lặp:

Hiển thị dấu nhắc ($) ---> Đọc lệnh ---> Tạo tiến trình ---> Đợi tiến trình kết thúc ---> Hiển thị dấu nhắc ($)

Khi chạy một shell_script, chính Shell sẽ phát sinh và quản lý tất cả các tiến trình con cần thiết để thực hiện công việc được mô tả trong file script.

1.2 Phân loại và Cây Tiến trình

Tiến trình được hiểu là việc thực thi một chương trình trong một môi trường hệ thống. Phân thành 2 loại:

  • Tiến trình hệ thống: Không gắn với bất kỳ terminal nào, được tạo ra khi khởi động OS hoặc bởi daemon do người quản trị đặt.
  • Tiến trình người dùng: Được tạo ra bởi người dùng trong phiên làm việc.

Các tiến trình được tổ chức dưới dạng Cây tiến trình (Process Tree): Tiến trình cha → Tiến trình con. Tiến trình init (PID 1) là tiến trình cha gốc của tất cả các tiến trình Shell khi đăng nhập.

Cách cấp quyền và thực hiện một shell_script:

$ chmod +x proc $ ./proc # Hoặc chạy trực tiếp với sh: $ sh proc

2. Liệt Kê Các Tiến Trình (`ps`)

Lệnh ps (Process Status) hiển thị danh sách các tiến trình đang hoạt động trong hệ thống:

$ ps PID TTY TIME CMD 3884 pts/1 00:00:00 bash 3955 pts/2 00:00:00 more 3956 pts/5 00:00:05 sqlplus

Ý nghĩa các thông số trong lệnh `ps`:

Cột thông số Ý nghĩa chi tiết
PID Số định danh tiến trình (Process Identity Number)
PPID Số định danh tiến trình cha (Parent Process Identity)
UID ID người sở hữu tiến trình (User ID)
TTY Terminal đang điều khiển tiến trình
TIME Thời gian tích lũy CPU đã sử dụng bởi tiến trình (Cumulative CPU time)
STIME Thời điểm tiến trình được khởi chạy (Start time)
C Chỉ số phần trăm sử dụng vi xử lý CPU phục vụ lập lịch
CMD / COMMAND Tên dòng lệnh sinh ra tiến trình đó

Các tùy chọn phổ biến của lệnh `ps`:

  • ps a: Hiển thị tất cả các tiến trình của mọi người dùng (all users).
  • ps u: Hiển thị chi tiết theo định dạng người dùng (User format: kèm UID, %CPU, %MEM, STIME).

5. Quản Lý Các Tín Hiệu (Signals) & Lệnh `trap`

5.1 Bảng danh sách các Tín hiệu (Signals) thông dụng

Signal 1 SIGHUP Cắt liên lạc kết nối với terminal (Disconnection / Hangup)

5.2 Lập trình xử lý Tín hiệu với lệnh `trap`

Lệnh trap cho phép định nghĩa hành động xử lý tùy chỉnh khi một tín hiệu phát sinh trong quá trình chạy script:

  • trap (không đối số): Liệt kê danh sách các tín hiệu và các lệnh xử lý đã đăng ký.
  • trap 'các_câu_lệnh' 2: Gán các câu lệnh custom để thực thi mỗi khi người dùng nhấn Ctrl + C / DEL (Signal 2).
  • trap '' 2: **Bỏ qua (Lờ đi)** tín hiệu phím DEL / Ctrl+C (người dùng nhấn DEL sẽ không làm gián đoạn script).
  • trap 2: **Khôi phục lại hành vi mặc định** của phím DEL / Ctrl+C.

1. Tổ Chức Hệ Thống Tập Tin Unix/Linux

1.1 3 Kiểu tập tin cơ bản

  • Tập tin bình thường (Regular file): Chứa dữ liệu dạng văn bản (ASCII/text) hoặc mã nhị phân (binary). Ký hiệu dạng -.
  • Tập tin thư mục (Directory file): Chứa danh sách các tên file/thư mục con. Ký hiệu dạng d.
  • Tập tin đặc biệt (Special/Device file): Đại diện cho các thiết bị phần cứng ngoại vi hoặc cơ chế truyền tin (bàn phím input, màn hình/máy in output). Ký hiệu dạng c (character) hoặc b (block).

1.2 Cấu trúc Cây hệ thống tập tin Linux

Các tập tin của Unix được tổ chức theo cấu trúc cây phân cấp bắt đầu từ thư mục gốc (Root - /):

Thư mục chuẩn Chức năng & Nội dung lưu trữ
/ Thư mục gốc (Root directory), chứa tất cả các thư mục khác
/bin Chứa các file thực thi nhị phân (binary commands) cần cho khởi động & chế độ đơn dùng (ls, cp, cat, bash...)
/boot Chứa Kernel image, grub và các file cấu hình khởi động hệ thống
/dev Chứa các file thiết bị phần cứng đặc biệt (sda, null, tty, zero...)
/etc Chứa tất cả các file cấu hình hệ thống (passwd, group, shadow, login.defs...)
/home Chứa thư mục cá nhân (home directory) của các người dùng thường
/lib Chứa các thư viện chia sẻ (shared libraries) cần cho các lệnh trong /bin và /sbin
/mnt Điểm gá lắp (mount point) tạm thời cho các thiết bị lưu trữ (USB, HDD ngoài...)
/proc Hệ thống tập tin ảo (virtual filesystem) lưu trữ thông tin về Kernel và tiến trình đang chạy
/sbin Chứa các lệnh thực thi dành riêng cho quản trị hệ thống (System Binaries: fdisk, reboot, ifconfig...)

2. Đường Dẫn & Thao Tác Di Chuyển Thư Mục

2.1 Đường dẫn tuyệt đối vs Tương đối

  • Đường dẫn tuyệt đối (Absolute Path): Chỉ rõ vị trí bắt đầu từ gốc / (ví dụ: /home/user1/notes). Luôn bắt đầu bằng /.
  • Đường dẫn tương đối (Relative Path): Bắt đầu tính từ thư mục làm việc hiện hành (ví dụ đứng tại /home thì gõ user1/notes).

Ký hiệu đặc biệt trong đường dẫn:

  • . : Thư mục hiện hành (current directory).
  • .. : Thư mục cha (parent directory).
  • ~ : Thư mục home của người dùng đang đăng nhập (Home directory).

2.2 Các lệnh di chuyển thư mục:

$ pwd /home/user1 $ cd /usr/bin $ pwd /usr/bin $ cd .. $ pwd /usr $ cd $ pwd /home/user1

3. Quyền Truy Cập & Quản Lý Người Dùng / Nhóm

3.1 Phân tích chi tiết một mục từ `ls -l`

  • - : Ký tự đầu tiên cho biết đây là file thường (nếu d là thư mục).

  • rw- : Quyền của Group (staff) → Đọc, Ghi, không được Thực thi.
  • r-- : Quyền của Other (người khác) → Chỉ được Đọc.
  • 1 : Số liên kết cứng (Hard links) trỏ đến file.
  • xyz : Tên tài khoản sở hữu (Owner).
  • staff : Tên nhóm sở hữu (Group).
  • 12 : Kích thước tập tin (bytes).
  • Mar 7 12:35 : Thời điểm chỉnh sửa gần nhất.
  • test : Tên tập tin.

4. Vào/Ra Chuẩn & Đổi Hướng (I/O Redirection & Pipes)

4.1 Các luồng Vào/Ra chuẩn (Standard I/O Streams)

  • stdin (Standard Input - Descriptor 0): Đầu vào chuẩn (Mặc định: Bàn phím).
  • stdout (Standard Output - Descriptor 1): Đầu ra chuẩn (Mặc định: Màn hình Console).
  • stderr (Standard Error - Descriptor 2): Đầu ra lỗi chuẩn (Mặc định: Màn hình Console).

4.2 Cú pháp Đổi hướng & Đường ống (Pipes)

Cú pháp Đổi hướng Ý nghĩa & Chức năng Ví dụ câu lệnh
lệnh > file Đổi hướng stdout vào file (Ghi đè - Overwrite) ls /bin > file1
lệnh >> file Đổi hướng stdout vào file (Ghi nối tiếp - Append) ls /bin >> file1
lệnh 2> file Đổi hướng lỗi stderr vào file (Ghi đè) ls /root 2> err.log
lệnh > file 2>&1 Đổi hướng cả stdout và stderr vào cùng 1 file ls /root > out.log 2>&1
lệnh 2> /dev/null Hủy bỏ toàn bộ thông báo lỗi ra thiết bị null find / -name "*.c" 2> /dev/null
lệnh < file Đổi hướng đầu vào stdin lấy dữ liệu từ file wc -l < file1
lệnh << STRING ... STRING Here-Document: Đọc dữ liệu đến khi gặp nhãn STRING cat > file1 << OK ... OK
lệnh1 | lệnh2 Đường ống (Pipe): Lấy stdout của lệnh1 làm stdin của lệnh2 ps -ef | grep bash
lệnh | tee file Đổi hướng kép: Vừa in ra màn hình vừa ghi ra file ps -ef | tee file_ps | grep root

  2. cd . → Vẫn ở thư mục hiện tại (/home/user1).
  3. cd .. → Lên thư mục cha (/home).
  4. cd user1 → Chuyển vào thư mục tài khoản login (/home/user1).
Bài 8: Di chuyển thư mục từ `/var/spool`

Giả sử đang ở /var/spool:

  • Thực hiện cd mail → Thư mục mới là /var/spool/mail.
  • Sau đó thực hiện cd ../spool/mail → Thư mục mới là /spool/mail.
Bài 9: Các câu hỏi thao tác thư mục trong `/var` và Home
  1. cd /var && ls -l | grep "^d" | wc -l → Đếm số thư mục con dưới /var.
  2. ls /sbin → Xem bình thường nếu có quyền đọc, hoặc báo Permission denied nếu bị cấm.
  3. mkdir /var/userxxx → Báo lỗi mkdir: cannot create directory '/var/userxxx': Permission denied vì user thường không có quyền ghi vào /var.
  4. cd ~ && mkdir ddddd → Tạo thành công vì user có toàn quyền ghi trong thư mục Home của mình.
  5. cd ddddd && echo "This is a message" > fffff && cat fffff → Tạo thành công file fffff chứa câu văn bản.
  6. Đứng tại /home/user1/ddddd gõ rmdir /home/user1/ddddd → Báo lỗi rmdir: failed to remove 'ddddd': Directory not empty (thư mục không rỗng) và không thể xóa thư mục khi đang đứng bên trong.

Bài 18: Giải thích Pipeline kết quả lệnh `sort`, `grep`, `wc`, `head`

Tạo file commands trong thư mục Home:

cal /usr/bin 9416 date /bin 2860 who /usr/bin 8692 cat /bin 18056 lpd /usr/sbin 42012
  1. sort -r commands | head -1 → Sắp xếp các dòng trong file commands theo thứ tự ngược bảng chữ cái (giảm dần) và lấy dòng đầu tiên lớn nhất (dòng who...).
  2. grep ^c commands | wc -l → Lọc các dòng bắt đầu bằng chữ 'c' (gồm cal và cat), sau đó đếm số dòng thu được $\rightarrow$ Kết quả in ra là 2.
  3. grep at commands | sort → Lọc các dòng chứa chuỗi 'at' (gồm date và cat), sau đó sắp xếp theo thứ tự bảng chữ cái $\rightarrow$ In ra dòng cat trước, date sau.
