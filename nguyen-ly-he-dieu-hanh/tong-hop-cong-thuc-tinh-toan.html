CẨM NANG ĐỌC HIỂU LỆNH C & CÔNG THỨC TÍNH TOÁN BÀI TẬP OS

Tổng hợp 100% chuẩn xác các lệnh C hệ thống (fork, wait, exec, pthread, semaphore) và công thức tính toán từ 7 chương bài giảng (CT178 / CT180 / CT107 - ĐHCT).

PHẦN 1. HƯỚNG DẪN ĐỌC HIỂU CODE C & LỆNH HỆ THỐNG (CHƯƠNG 3, 4, 5)

1.1 Lệnh fork() & Quy Tắc Đếm Tiến Trình (Chương 3)

Bản chất: fork() tạo ra 1 tiến trình con là bản sao chính xác của tiến trình cha tại thời điểm gọi.

🔑 3 Quy Tắc Vàng Khi Đọc Code fork():
  1. Giá trị trả về của fork():
    - Trả về 0 trong tiến trình con (Child Process).
    - Trả về PID con (>0) trong tiến trình cha (Parent Process).
    - Trả về -1 nếu bị lỗi.
  2. Số lượng tiến trình được tạo ra:
    - Nếu có $k$ lệnh fork() độc lập nối tiếp nhau $\rightarrow$ Tổng số tiến trình tạo ra là $2^k$.
    - Số tiến trình con được tạo mới: $N_{\text{child}} = 2^k - 1$.
  3. Không gian bộ nhớ riêng biệt (Copy-on-Write): Sau khi fork(), tiến trình con và cha có bộ nhớ độc lập. Thay đổi biến ở tiến trình con KHÔNG làm thay đổi biến ở tiến trình cha!

Ví dụ Đọc Code & Đếm Tiến Trình Cụ Thể (Slide Ch3-p20):

#include <stdio.h> #include <unistd.h> #include <stdlib.h> #include <sys/wait.h> int main() { int pid = fork(); // Tạo tiến trình con if (pid < 0) { fprintf(stderr, "Fork failed"); exit(-1); } else if (pid == 0) { // Tiến trình con nạp chương trình /bin/ls execlp("/bin/ls", "ls", NULL); } else { // Tiến trình cha chờ con hoàn thành wait(NULL); printf("Child completed\n"); exit(0); } }

Kết quả: Tiến trình cha tạm dừng chờ tiến trình con nạp và chạy xong câu lệnh ls, sau đó mới in "Child completed".

1.2 Lệnh wait() & Tiến Trình Zombie/Orphan (Chương 3)

Bản chất: Buộc tiến trình cha tạm dừng (WAITING) đến khi tiến trình con kết thúc để thu hồi tài nguyên PCB.

  • wait(NULL); → Chờ bất kỳ tiến trình con nào kết thúc.
  • Zombie Process: Tiến trình con đã kết thúc nhưng tiến trình cha chưa gọi wait() $\rightarrow$ PCB của con vẫn nằm trong bảng tiến trình.
  • Orphan Process: Tiến trình cha kết thúc trước khi tiến trình con hoàn thành $\rightarrow$ Tiến trình con bị mồ côi, được HĐH nhận làm con của tiến trình init (PID 1).
1.3 Họ Lệnh execlp() (Chương 3)

Bản chất: Nạp một chương trình mới từ đĩa ghi đè hoàn toàn lên không gian địa chỉ (code, data, stack) của tiến trình gọi.

⚠️ Quy Tắc Vàng Khi Đọc Code Có execlp():
Nếu lệnh execlp() thực thi THÀNH CÔNG, toàn bộ mã lệnh nằm BÊN DƯỚI lệnh execlp() trong file C sẽ KHÔNG BAO GIỜ ĐƯỢC THỰC THI!
1.4 Đa Luồng POSIX Threads & Windows API (Chương 4)

Đơn vị cấp phát CPU trong các HĐH hiện đại là Luồng (Thread) thay vì Tiến trình.

📋 Các hàm pthread cốt lõi:
  • pthread_create(&tid, NULL, runner, arg); → Tạo luồng mới.
  • pthread_join(tid, NULL); → Luồng chính chờ luồng con kết thúc.
  • pthread_exit(0); → Kết thúc luồng hiện tại.
1.5 Chỉ Thị Đồng Bộ Hóa (Chương 5)

1. Thao tác nguyên tử Semaphore $S$:

// Thao tác wait(S) / P(S): void wait(semaphore S) { S.value--; if (S.value < 0) { add this process to S.L; block(); // Tạm dừng không chờ bận } } // Thao tác signal(S) / V(S): void signal(semaphore S) { S.value++; if (S.value <= 0) { remove a process P from S.L; wakeup(P); // Đánh thức tiến trình chờ } }

Ghi chú: Nếu $S.value < 0$, giá trị tuyệt đối $|S.value|$ chính là số tiến trình đang bị khóa trong hàng đợi $S.L$.

2. Chỉ thị nguyên tử phần cứng (Hardware Atomic Instructions):

// Chỉ thị test_and_set boolean test_and_set(boolean *target) { boolean rv = *target; *target = true; return rv; } // Chỉ thị compare_and_swap / swap boolean compare_and_swap(boolean *target, boolean expected, boolean new_val) { boolean temp = *target; if (*target == expected) *target = new_val; return temp; }

PHẦN 2. CÔNG THỨC & THUẬT TOÁN ĐỊNH THỜI CPU (CHƯƠNG 4)

2.1 Các Chỉ Số Đánh Giá Định Thời CPU

Cho các tiến trình $P_i$ có Thời điểm đến $A_i$ (Arrival Time) và Thời gian CPU burst $B_i$:

  • Thời điểm hoàn thành $C_i$ (Completion Time): Thời điểm tiến trình $P_i$ kết thúc hoàn toàn.
  • Thời gian xoay vòng $T_{\text{tat}}^i$ (Turnaround Time):
    $$T_{\text{tat}}^i = C_i - A_i$$
  • Thời gian chờ $T_w^i$ (Waiting Time):
    $$T_w^i = T_{\text{tat}}^i - B_i$$
  • Thời gian phản hồi $T_{\text{res}}^i$ (Response Time):
    $$T_{\text{res}}^i = T_{\text{first\_exec}}^i - A_i$$
  • Thời gian chờ trung bình ($\bar{T}_w$) & Xoay vòng trung bình ($\bar{T}_{\text{tat}}$):
    $$\bar{T}_w = \frac{1}{N} \sum_{i=1}^{N} T_w^i, \quad \bar{T}_{\text{tat}} = \frac{1}{N} \sum_{i=1}^{N} T_{\text{tat}}^i$$
2.2 Công Thức Trung Bình Mũ Dự Đoán CPU Burst (Chương 4 Slide 20)

Thuật toán SJF dự đoán thời lượng CPU burst tiếp theo $\tau_{n+1}$ thông qua lịch sử các lần trước:

$$\tau_{n+1} = \alpha t_n + (1 - \alpha)\tau_n$$
  • $t_n$: Thời gian sử dụng CPU thực tế ở lần thứ $n$.
  • $\tau_n$: Thời gian ước lượng ở lần thứ $n$.
  • $\alpha \in [0, 1]$: Hệ số trung bình mũ điều chỉnh trọng số lịch sử (thường chọn $\alpha = 1/2$).
  • Trường hợp đặc biệt: $\alpha = 0 \implies \tau_{n+1} = \tau_n$ (bỏ qua thực tế); $\alpha = 1 \implies \tau_{n+1} = t_n$ (chỉ tính thực tế gần nhất).
2.3 Mô Hình Hàng Đợi - Công Thức Little (Chương 4 Slide 43)

Tính toán chiều dài hàng đợi trung bình trong mô hình hàng đợi định thời:

$$n = \lambda \times W$$
  • $n$: Chiều dài hàng đợi trung bình (số tiến trình).
  • $\lambda$: Tỷ lệ đến trung bình của các tiến trình mới (tiến trình/giây).
  • $W$: Thời gian chờ trung bình trong hàng đợi (giây).

PHẦN 3. BẾ TẮC & THUẬT TOÁN BANKER (CHƯƠNG 6)

3.1 Ma Trận Nhu Cầu Còn Lại $Need$

Cho $n$ tiến trình $P_0..P_{n-1}$ và $m$ loại tài nguyên $R_1..R_m$:

$$Need[i][j] = Max[i][j] - Allocation[i][j]$$
📋 Quy Trình Kiểm Tra Trạng Thái An Toàn (Safety Algorithm - Ch6 Slide 29):
  1. Khởi tạo: $Work = Available$ (vector $1 \times m$), $Finish[i] = false$ với mọi $i = 0..n-1$.
  2. Tìm $i$ thỏa mãn 2 điều kiện:
    a) $Finish[i] == false$
    b) $Need[i] \le Work$ (tức $Need[i][j] \le Work[j]$ với mọi $j=1..m$)
    Nếu không tìm thấy $i$ thỏa mãn $\rightarrow$ Chuyển sang Bước 4.
  3. Cập nhật giả định khi $P_i$ hoàn thành:
    $$Work = Work + Allocation[i]$$
    $$Finish[i] = true$$
    Quay lại Bước 2.
  4. Nếu $Finish[i] == true$ với mọi $i \rightarrow$ Hệ thống ở **Trạng Thái An Toàn**. Chuỗi an toàn: $\langle P_{s1}, P_{s2}, ..., P_{sn} \rangle$. Ngược lại $\rightarrow$ **Trạng Thái Không An Toàn (Unsafe)**.
3.2 Thuật Toán Yêu Cầu Tài Nguyên (Resource-Request Algorithm - Ch6 Slide 30-31)

Khi tiến trình $P_i$ gửi yêu cầu $Request_i$:

  1. Nếu $Request_i \le Need_i \rightarrow$ Sang Bước 2. Ngược lại báo lỗi vì vượt quá khai báo tối đa.
  2. Nếu $Request_i \le Available \rightarrow$ Sang Bước 3. Ngược lại $P_i$ phải chờ do chưa đủ tài nguyên rảnh.
  3. Cập nhật giả định:
    $$Available = Available - Request_i$$
    $$Allocation[i] = Allocation[i] + Request_i$$
    $$Need[i] = Need[i] - Request_i$$
  4. Chạy Safety Algorithm. Nếu An toàn $\rightarrow$ Cấp phát thật. Nếu Không an toàn $\rightarrow$ Khôi phục lại trạng thái cũ, $P_i$ phải chờ.

PHẦN 4. QUẢN LÝ BỘ NHỚ & DỊCH ĐỊA CHỈ PHÂN TRANG (CHƯƠNG 7)

4.1 Công Thức Dịch Địa Chỉ Phân Trang (Paging)

Cho Kích thước trang / Frame $P = 2^n$ bytes (ví dụ $P = 4KB = 4096$ bytes $\rightarrow n = 12$ bits offset).

  • Số bit dành cho Offset $d$: $n = \log_2(P)$.
  • Tách Địa chỉ Logic $A$ thành cặp $(p, d)$:
    $$p = \lfloor A / P \rfloor \quad (\text{Số trang - Page number})$$
    $$d = A \pmod P \quad (\text{Độ lệch - Offset})$$
  • Tra Bảng Trang (Page Table): Tìm $f = PageTable[p]$ (Số khung trang - Frame number).
  • Tính Địa chỉ Vật lý $A_{\text{physical}}$ trong RAM:
    $$A_{\text{physical}} = (f \times P) + d$$
📐 Ví dụ tính toán (Ch7 Slide 29):
Kích thước trang $P = 4$ bytes. Bộ nhớ vật lý $32$ bytes ($8$ khung).
Địa chỉ Logic $A = 3 \rightarrow p = \lfloor 3 / 4 \rfloor = 0$, $d = 3 \pmod 4 = 3$.
Tra bảng trang: $PageTable[0] = 5 \rightarrow$ Địa chỉ vật lý $A_{\text{physical}} = (5 \times 4) + 3 = 23$.
4.2 Thời Gian Truy Xuất Hiệu Dụng TLB (Effective Access Time - EAT - Ch7 Slide 35)

Cho $\varepsilon$ là thời gian tra bộ đệm TLB, $m$ là thời gian truy xuất RAM, và $\alpha$ là Tỷ lệ tìm thấy trong TLB (Hit ratio):

$$EAT = (\varepsilon + m)\alpha + (\varepsilon + 2m)(1 - \alpha) = (2 - \alpha)m + \varepsilon$$

Ví dụ đề bài: $\varepsilon = 20\text{ns}$, $\alpha = 0.8$, $m = 100\text{ns} \implies EAT = (2 - 0.8) \times 100 + 20 = 140\text{ns}$.

4.3 Địa Chỉ Phân Đoạn (Segmentation - Ch7 Slide 55-56)

Địa chỉ logic gồm cặp $(s, d)$ với $s$ là số phân đoạn, $d$ là độ dời offset.

  • Kiểm tra tính hợp lệ: Nếu $d \ge \text{limit}[s] \rightarrow$ Báo lỗi **Segment Fault Trap**.
  • Nếu hợp lệ: $\text{Địa chỉ vật lý} = \text{base}[s] + d$.

Dạng bài tập / Nguyên lý Công thức / Quy tắc tính toán chuẩn xác
Số tiến trình tạo ra bởi $k$ lệnh fork() Tổng số tiến trình = $2^k$. Số tiến trình con mới = $2^k - 1$.
Giá trị trả về của fork() Con: pid == 0. Cha: pid > 0 (chứa PID con). Lỗi: pid < 0.
Mã lệnh bên dưới execlp() KHÔNG BAO GIỜ chạy nếu execlp() nạp chương trình thành công.
Chỉ số Định thời CPU ($T_{\text{tat}}$, $T_w$, $T_{\text{res}}$) $T_{\text{tat}} = C_i - A_i$ • $T_w = T_{\text{tat}} - B_i$ • $T_{\text{res}} = T_{\text{first\_exec}} - A_i$.
Dự đoán CPU Burst tiếp theo trong SJF $\tau_{n+1} = \alpha t_n + (1 - \alpha)\tau_n$ với $\alpha \in [0, 1]$.
Mô hình hàng đợi Little $n = \lambda \times W$ ($n$: số tiến trình hàng đợi, $\lambda$: tỷ lệ đến, $W$: thời gian chờ).
Bài toán Banker ($Need$ & An toàn) $Need[i][j] = Max[i][j] - Allocation[i][j]$. Cấp khi $Need_i \le Work$ và giữ trạng thái Safe.
Tách địa chỉ Phân trang $(p, d)$ Offset $d = \text{Logical} \pmod P$, Trang $p = \lfloor \text{Logical} / P \rfloor$. Địa chỉ RAM $= (f \times P) + d$.
